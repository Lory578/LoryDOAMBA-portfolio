### PHASE 3 : BLOG, ADMIN ET BASE DE DONNÉES (Supabase : PostgreSQL + Auth + Storage)

**1. Base de données (fournis le SQL complet à exécuter dans Supabase)**
Table `posts` :
- id (uuid, clé primaire), slug (texte unique), status (« draft » ou « published »)
- title_fr, title_en, excerpt_fr, excerpt_en (texte)
- content_fr, content_en (texte, Markdown)
- cover_image_url (texte), tags (tableau de texte)
- published_at (timestamptz, nul tant que brouillon), created_at, updated_at (timestamptz)
Table `site_settings` (une seule ligne) : cv_url (texte), cv_updated_at (timestamptz).
Buckets Storage : `blog-images` (public en lecture) et `documents` (public en lecture, pour le CV).
Row Level Security :
- Lecture publique de `posts` uniquement quand status = 'published'.
- Lecture et écriture complètes sur `posts`, `site_settings` et les buckets uniquement pour l'utilisateur administrateur identifié par son email (variable ADMIN_EMAIL).
Inclus : tables, index sur slug et published_at, politiques RLS, trigger updated_at.
